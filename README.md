# OLX Telegram Bot

Телеграм-бот, який стежить за пошуковими запитами на OLX і надсилає нові оголошення в чат.

## Структура проєкту

```
run.py                      # точка входу для локальної розробки (polling)
web.py                       # точка входу для Render (webhook, HTTP-сервер)
render.yaml                  # Render Blueprint для деплою одним кліком
bot/
  config.py                 # завантаження налаштувань з .env
  main.py                   # запуск у режимі polling (run.py)
  webhook_app.py            # запуск у режимі webhook (web.py, для Render)
  scheduler.py              # фонова перевірка підписок за розкладом
  db/
    database.py             # SQLite: підписки та вже показані оголошення
  olx/
    parser.py               # завантаження і парсинг сторінки пошуку OLX
    models.py                # dataclass Ad
  handlers/
    start.py                # /start, /help
    subscriptions.py        # /add, /list, /remove, /check
data/                        # тут лежить файл SQLite (створюється автоматично)
```

## Встановлення

1. Створіть і активуйте віртуальне середовище (або скористайтесь наявним `.venv`):

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```

2. Встановіть залежності:

   ```bash
   pip install -r requirements.txt
   ```

3. Скопіюйте `.env.example` у `.env` і вставте токен бота, отриманий від [@BotFather](https://t.me/BotFather):

   ```bash
   cp .env.example .env
   ```

   `.env` вже додано в `.gitignore` — токен ніколи не потрапить у git.

## Запуск

```bash
python run.py
```

## Використання в Telegram

- `/add iphone https://www.olx.ua/uk/list/q-iphone-15/` — додати відстеження пошуку
- `/list` — показати активні підписки
- `/remove <id>` — видалити підписку
- `/check` — перевірити всі підписки прямо зараз
- `/help` — довідка

Після додавання підписки бот запам'ятовує вже наявні оголошення й надалі кожні
`CHECK_INTERVAL_MINUTES` хвилин (за замовчуванням 10) надсилає лише нові.

## Деплой на Render (безкоштовний план)

Бот на Render працює у режимі **webhook** (`web.py`), а не `run.py` — Telegram сам
надсилає оновлення на публічну адресу сервісу, тож не потрібен постійний процес
polling. Для цього:

1. Запуште репозиторій на GitHub (див. розділ нижче).
2. На [render.com](https://render.com) → **New +** → **Blueprint** → оберіть цей
   репозиторій. Render підхопить `render.yaml` і сам налаштує білд/старт-команди.
3. Під час створення Render попросить задати секретні змінні (позначені
   `sync: false` у `render.yaml`) — впишіть:
   - `BOT_TOKEN` — токен від @BotFather;
   - `WEBHOOK_SECRET` — будь-який випадковий рядок, наприклад згенерований через
     `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
4. `WEBHOOK_URL` задавати не потрібно — код бере адресу сервісу автоматично зі
   змінної `RENDER_EXTERNAL_URL`, яку Render підставляє сам.
5. Після деплою Render викличе `python web.py`, бот сам зареєструє webhook у
   Telegram при старті.

### Важливі застереження безкоштовного плану

- **Сон при бездіяльності.** Безкоштовний Web Service на Render засинає після
  ~15 хв без HTTP-запитів і прокидається лише на новий запит. Це означає:
  - перше повідомлення після сну прийде із затримкою (десятки секунд — поки
    інстанс піднімається), Telegram у цей час просто повторює доставку;
  - фонова перевірка підписок (`CHECK_INTERVAL_MINUTES`) працює лише поки
    процес живий — поки бот «спить», нові оголошення НЕ перевіряються. Щойно
    хтось напише боту (або сам зайде і торкне сервіс), перевірки відновляться.
  - Якщо потрібна гарантована перевірка кожні N хвилин 24/7 — це вимагає
    платного плану Render (Starter і вище, без сну) або окремого зовнішнього
    пінгера, що будить сервіс за розкладом.
- **Диск не постійний.** На безкоштовному плані файл SQLite (`data/olx_bot.db`)
  живе, поки живий поточний інстанс, але скидається при кожному новому деплої
  (наприклад, після `git push`). Підписки доведеться додавати заново після
  оновлення коду. Для постійного диска потрібен платний план з Persistent Disk.

## Примітки

- Парсер спирається на атрибути `data-testid` у розмітці olx.ua. Якщо OLX змінить
  верстку, потрібно буде оновити селектори в `bot/olx/parser.py`.
- Для продакшн-розгортання на власному сервері (VPS, systemd, Docker тощо)
  простіше тримати процес `python run.py` (polling) запущеним постійно —
  тоді немає ні сну, ні втрати диска.
